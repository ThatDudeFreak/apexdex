# Apexdex

**The Apex Legends data index.** Live map rotation, Predator RP cutoffs,
weekly crafting rotation, and legend abilities — every page auto-refreshes
via Next.js ISR.

Built on Next.js (App Router) + TypeScript + Tailwind, fed by the unofficial
[apexlegendsstatus.com](https://apexlegendsstatus.com) /
[mozambiquehe.re](https://api.mozambiquehe.re) API.

## Getting started

```bash
# 1. Register a free API key (Discord login). Only one key per project/person.
#    https://apexlegendsapi.com/auth

# 2. Drop the key into a local env file (this file is gitignored).
cp .env.local.example .env.local
# then edit .env.local and set APEX_API_KEY=<your key>

# 3. Install + run.
npm install
npm run dev
# open http://localhost:3000
```

On the first successful fetch of each endpoint, the raw JSON is written to
`.cache/<endpoint>.raw.json` and logged once to the terminal so you can
inspect the actual shape (and refine the TypeScript types in
[`lib/apex.ts`](lib/apex.ts) accordingly).

## Routes

| Path | What it shows | ISR `revalidate` |
| --- | --- | --- |
| `/` | Landing + nav to every page. `WebSite` JSON-LD with `SearchAction`. | static |
| `/map-rotation` | Current map per mode (BR pubs, ranked, LTM, control, etc.), client-side countdown to the next swap, and what's next. | **60 s** |
| `/predator-rp-cutoff` | RP cutoff to hit Apex Predator on PC / PS / Xbox / Switch, plus Master+ player counts and cutoff rank. | **3600 s** |
| `/crafting-rotation` | The bundles currently in replicators with materials cost per item. | **21 600 s** |
| `/legends/[slug]` | Templated legend page: class, tagline, passive/tactical/ultimate. Seed roster of 5 legends in [`data/legends.json`](data/legends.json) — Wraith, Bloodhound, Pathfinder, Lifeline, Bangalore. | static (built from `generateStaticParams`) |
| `/sitemap.xml` | Auto-generated; includes every legend slug. | per build |
| `/robots.txt` | Auto-generated. | per build |

## SEO bits already wired up

- **Dynamic `<title>` and meta description** per page, derived from the
  live data (e.g. the map rotation page advertises the current BR map and
  ranked map in the title).
- **Open Graph** mirrors of the above.
- **Canonical URLs** via `metadata.alternates.canonical`.
- **JSON-LD** on every page:
  - `/` — `WebSite` + `SearchAction`
  - `/map-rotation` — `WebPage` with `mainEntity` listing the current map per mode and `dateModified`
  - `/predator-rp-cutoff` — `Dataset` with `variableMeasured` per platform
  - `/crafting-rotation` — `ItemList` with `ListItem` per craftable
  - `/legends/[slug]` — `VideoGameCharacter` with `characterClass`, `homeLocation`, `knowsAbout` (abilities)
- **Visible "Last updated: <UTC>"** on every data-backed page.
- **Sitemap + robots** generated by `app/sitemap.ts` and `app/robots.ts`.

## Resilience

`lib/apex.ts` centralises the API client:

- API key read from `APEX_API_KEY` (never hardcoded; never exposed to the client).
- Every request is wrapped in `try/catch`.
- Two-layer cache: in-memory `Map` for the running process, and on-disk
  JSON files under `.cache/` so dev reloads and ISR regeneration don't
  hammer the API (it has no uptime guarantee).
- On any network/HTTP failure the layer falls back to the cached payload
  and flags `stale: true`; pages render a yellow banner instead of crashing.
- First successful fetch of each endpoint writes the raw JSON shape to
  `.cache/<endpoint>.raw.json` and logs a preview so you can inspect it.

If neither network nor cache works, pages render a red "couldn't reach the
API and no cache available" panel instead of throwing a 500.

## Long-tail page potential — endpoint richness

Based on the [API docs](https://apexlegendsapi.com) and the API's wider
catalogue, here is the rough page-yield-per-endpoint estimate (refine after
you've run a live fetch and inspected the raw JSON in `.cache/`):

| Endpoint | Page yield | Why |
| --- | --- | --- |
| `/maprotation?version=2` | **1 page**, but high-frequency updates → strong freshness signal. | One canonical page per mode is the SEO winner; per-mode subpages would cannibalise. |
| `/predator` | 4–5 pages (one per platform) + a comparison page. | Platform-specific RP cutoff queries get search traffic individually. |
| `/crafting` | 1–2 pages with extremely tight refresh cadence. | "Apex crafting rotation this week" is a high-intent recurring query. |
| `/bridge` (player stats) | **Effectively unlimited.** | One templated page per legend × tracker combination, plus a page per public player UID. This is the long-tail goldmine. |
| `/games` (recent matches) | Per-player page deepening. | Match history pages with shareable URLs. |
| `/servers` | 1 page. | Status board. |
| `/news` (in-game) / map asset assets | Per-article. | The `/maprotation` payload includes asset URLs you can reuse on map landing pages. |

The pages currently scaffolded only touch three endpoints (`maprotation`,
`predator`, `crafting`) plus a static legends seed. The richest expansion
path is `/bridge` — once you confirm what tracker fields it returns for
a given player + legend, a templated page per `(player, legend)` or
`(legend, tracker-type)` is a real pSEO surface.

> After you run with a live key, look at `.cache/_maprotation.raw.json`,
> `.cache/_predator.raw.json`, and `.cache/_crafting.raw.json` to see the
> exact response keys — then tighten the `MapRotationResponse`,
> `PredatorResponse`, and `CraftingResponse` types in `lib/apex.ts`.

```

  page.tsx                 landing page
  not-found.tsx            404
  robots.ts                /robots.txt generator
  sitemap.ts               /sitemap.xml generator (includes every legend slug)

  DataMeta.tsx             stale banner + last-updated footer
data/
  legends.json             seed roster (5 legends)
lib/
  apex.ts                  API client + cache + stale fallback + raw-JSON logger
  legends.ts               legend data loader

```

## Out of scope (intentionally)

Auth, analytics, ads/affiliate, full legend/weapon catalogue, deployment,
image/avatar hosting, image OG cards. Add them after the data shape is
locked in.

## Notes on the unofficial API

- The API is unofficial. It has no uptime guarantee and shapes can change
  without warning — that's why the data layer caches aggressively and
  logs the raw JSON on first fetch.
- Default rate limit is **5 req/s** across all endpoints per key, which
  ISR with 60 s / 3600 s / 21 600 s revalidation is comfortably under.
- The usage rules at <https://apexlegendsapi.com/usage-rules> require a
  visible "Data from apexlegendsstatus.com" credit when displaying server
  status. We display it in the footer for safety.
